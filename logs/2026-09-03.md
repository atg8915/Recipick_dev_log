## 백엔드
### 기능
- 식단표 월간 통계 조회 API(`GET /calendar/info`) 추가: 총/일평균 칼로리, 채움률, 일평균 탄·단·지, 이번 달 TOP1 레시피
- `CalendarInfoVO` 신설, `CalendarService`/`CalendarServiceImpl`에 `selectCalendarInfo` 구현, MyBatis 매퍼(`calendarItem-mapper.xml`)에 통계 집계 쿼리 2종(`selectCalendarInfo`, `selectTop1Recipe`) 추가

### 이슈 / 해결
- [채움률(%) 계산을 위해 "이번 달 총 일수"가 필요한데 SQL만으로는 월별 일수(28~31일)를 안전하게 구하기 까다로움]
- 원인: Oracle에서 월별 일수를 직접 계산하면 로직이 복잡해짐
- 해결: 자바에서 `YearMonth`로 일수를 미리 계산해 파라미터로 넘기고, TOP1 레시피는 별도 서브쿼리로 분리해 메인 통계 쿼리와 합침
  ```java
  YearMonth ym = YearMonth.of(Integer.parseInt(year), Integer.parseInt(month));
  int daysInMonth = ym.lengthOfMonth();

  CalendarInfoVO info = cMapper.selectCalendarInfo(user_id, year, month, daysInMonth);
  Map<String, Object> top1 = cMapper.selectTop1Recipe(user_id, year, month);
  if (top1 != null) {
      info.setTop1_rcp_seq(((Number) top1.get("TOP1_RCP_SEQ")).intValue());
      info.setTop1_nm((String) top1.get("TOP1_NM"));
      info.setTop1_count(((Number) top1.get("TOP1_COUNT")).intValue());
  }
  ```
  (파일: src/main/java/com/sist/web/service/CalendarServiceImpl.java, 커밋: fa0ac37)

### 이슈 / 해결
- [백엔드가 월(month)을 `MM` 2자리 문자열로 비교하는데, 프론트에서 숫자형 month를 그대로 보내면 비교가 어긋날 수 있음]
- 원인: 서버 쿼리 조건이 `YYYY`/`MM` 문자열 포맷을 기대함
- 해결:
  ```javascript
  const params = new URLSearchParams({
    user_id: userId.value ?? userId,
    year: year.value, // 백엔드에서 YYYY로 비교하니까 그대로
    month: String(month.value).padStart(2, "0"),
    // 백엔드가 MM 2자리로 비교하니까 9월이면 09로 맞춰줘야 함
  });
  ```
