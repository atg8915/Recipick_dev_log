- 원인: 프론트/백엔드 작업 순서가 어긋나 프론트에서 먼저 삭제 요청을 붙였고, 백엔드 엔드포인트는 이후에 구현됨
- 해결: Mapper/Service/Controller에 삭제 로직을 추가해 프론트 요청 스펙과 맞춤
  ```java
  @DeleteMapping("/calendar/item")
  public ResponseEntity<Integer> calendar_item_delete(
          @RequestParam("user_id") int user_id,
          @RequestParam("meal_date") String meal_date,
          @RequestParam("meal_type") String meal_type
          )
  {
      int result;
      try {
          result = cService.deleteCalendarItem(user_id, meal_date, meal_type);
      } catch (Exception ex) {
          ex.printStackTrace();
          return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR).build();
      }
      return ResponseEntity.ok(result);
  }
  ```
  (파일: CalendarRestController.java, CalendarServiceImpl.java, calendarItem-mapper.xml, 커밋: 990a5d6)

  ```javascript
  async function deleteItem(dateStr, mealType){
    try {
      const params = new URLSearchParams({
        user_id: userId.value ?? userId,
        meal_date: dateStr,
        meal_type: mealType,
      });
      const res = await fetch(`${API_BASE}/calendar/item?${params.toString()}`, {
        method: "DELETE",
      });
      if (!res.ok) throw new Error(`삭제 실패 : ${res.status}`);
      await loadCalendar();
    } catch (e) {
      errorMsg.value = "레시피 삭제 실패";
      console.error(e);
    }
  }
  ```
  (파일: src/composables/useCalendarItems.js, src/components/calendar/CalendarGrid.vue, 커밋: 778a39b)
